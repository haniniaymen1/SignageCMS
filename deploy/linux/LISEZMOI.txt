SignageCMS — Scripts Linux
==========================

CONTENU DU DOSSIER
------------------
  install.sh        Installation COMPLÈTE du serveur CMS (recommandé) :
                    utilitaires + Node.js 20 LTS + LibreOffice + Poppler +
                    déploiement /opt/signagecms + .env + npm/Prisma/build +
                    service systemd + pare-feu + vérification finale.
  start.sh          Lancement du serveur EN ARRIERE-PLAN par défaut
                    (service.log + server.pid, ne bloque pas le terminal,
                    continue après fermeture du terminal). Options :
                    --foreground (premier plan), --stop, --restart,
                    --status. Si le build production est absent, il est
                    construit automatiquement (npm install + Prisma +
                    build, journal build.log) ; --no-build pour désactiver.
  stop.sh           Arrêt PROPRE dédié : SIGTERM, attente 10 s, SIGKILL si
                    nécessaire ; replis server.pid -> ligne de commande ->
                    port d'écoute ; arrête aussi le service systemd s'il
                    existe ; ne tue JAMAIS un autre processus.
  install-tools.sh  Uniquement LibreOffice + Poppler (multi-distributions).
  LISEZMOI.txt      Ce fichier.

  Raccourcis créés à la racine par install.sh : ./start.sh et ./stop.sh.

INSTALLATION COMPLÈTE EN UNE COMMANDE (recommandé)
--------------------------------------------------
  sudo bash deploy/linux/install.sh

  Le script recherche d'abord l'archive SignageCMS-Serveur-*.zip à côté de
  lui et à l'emplacement courant. S'il n'en trouve pas (et qu'aucune
  installation n'existe dans /opt/signagecms), il TÉLÉCHARGE automatiquement
  la dernière archive depuis l'URL publique du projet, vérifie son
  intégrité, puis poursuit. Vous pouvez aussi :

  sudo bash deploy/linux/install.sh --zip /chemin/SignageCMS-Serveur-v3.11.24.zip
  sudo bash deploy/linux/install.sh --url https://serveur/SignageCMS-Serveur.zip

  L'intégrité de l'archive (fournie ou téléchargée) est toujours contrôlée
  avant extraction ; en cas d'archive corrompue, le script s'arrête avec un
  message clair. Si une installation existe déjà dans /opt/signagecms,
  l'archive est optionnelle (ré-extraction écrasante si fournie).
  Options utiles :

    --zip FICHIER      chemin de l'archive serveur (sinon auto-téléchargement)
    --url URL          URL de téléchargement de l'archive (surcharge)
    --port 8080        port d'écoute du CMS (défaut 3000)
    --dir /opt/moncms  dossier d'installation (défaut /opt/signagecms)
    --no-service       ne crée pas le service systemd
    --no-firewall      ne modifie pas le pare-feu

  Le script est idempotent : réexécutable sans risque.

LANCER ET ARRÊTER LE SERVEUR
----------------------------
  ./start.sh                              # arrière-plan (par défaut)
  bash deploy/linux/start.sh --foreground # premier plan (Ctrl+C)
  bash deploy/linux/start.sh --status     # état + version API
  bash deploy/linux/start.sh --restart    # redémarre
  ./stop.sh                               # arrêt propre
  bash deploy/linux/stop.sh               # idem

  Le démarrage est silencieux : le serveur tourne en arrière-plan et
  continue après la fermeture du terminal ; les démarrages multiples sont
  refusés (server.pid + détection par API et par ligne de commande) et un
  conflit de port est signalé dans service.log.

  PORT DU SERVEUR : modifiable dans le fichier .env (ligne PORT=3000).
  Pris en compte au prochain démarrage : ./stop.sh puis ./start.sh,
  ou directement ./start.sh --restart.
  Les scripts start.sh et stop.sh lisent .env automatiquement.

  Si le service systemd a été créé par install.sh, préférez :
  sudo systemctl status|restart|stop signagecms
  (le service lit aussi le PORT du .env depuis v3.11.25)

IDENTIFIANTS ADMIN
------------------
  Créés dès l'installation : le mot de passe aléatoire initial est écrit dans
  db/admin-credentials.txt (à supprimer après la 1re connexion) et affiché à
  la fin de l'installation / au démarrage du serveur. Si le fichier n'existe
  pas encore, validez une fois le formulaire de connexion (admin + mot de
  passe quelconque) : le compte est créé et le fichier apparaît.

  Mot de passe perdu ? Réinitialisez le compte en une commande :
    sudo bash deploy/linux/reset-admin.sh
  (Windows : deploy\windows\reset-admin.bat) — un nouveau mot de passe
  aléatoire est affiché immédiatement et le fichier est réécrit, sans
  redémarrage ni essai de connexion à l'aveugle.

OUTILS DE CONVERSION SEULS (LibreOffice + Poppler)
--------------------------------------------------

Pour afficher les PowerPoint (PPT/PPTX/PPS/PPSX/ODP) et les PDF sur les
écrans, le serveur CMS a besoin de DEUX outils installés une seule fois :

  - LibreOffice : PPT -> PDF     (soffice --headless)
  - Poppler     : PDF -> PNG par diapositive (pdftoppm)

INSTALLATION AUTOMATIQUE
------------------------
  sudo bash deploy/linux/install-tools.sh

Le script détecte votre distribution (Ubuntu/Debian, RHEL/Fedora, openSUSE,
Arch, Alpine), installe les paquets officiels, puis vérifie le résultat.
Il est idempotent : le relancer ne réinstalle rien.

CAS PARTICULIERS
----------------
  - Pas de sudo ?
      bash deploy/linux/install-tools.sh --no-sudo
    → télécharge l'archive officielle LibreOffice (documentfoundation.org)
      et l'installe dans $HOME ; ajoutez alors dans le fichier .env du CMS :
      SOFFICE_PATH=/home/<user>/.local/bin/soffice
      (Poppler reste à faire installer par l'administrateur : poppler-utils)

  - Déjà installé ailleurs (chemin non standard) ?
      Déclarez-le dans .env :
      SOFFICE_PATH=/chemin/vers/soffice
      PDFTOPPM_PATH=/chemin/vers/pdftoppm

VÉRIFICATION
------------
  soffice --version && pdftoppm -v

Le CMS affiche aussi l'état de ces outils dans la bibliothèque de médias
(badge « Non converti » + bouton « Reconvertir ») et au démarrage du serveur
(avertissement console si absent).

Après installation : redémarrez le CMS, puis cliquez « Reconvertir » sur les
médias concernés — ou réimportez-les.
